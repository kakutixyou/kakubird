① GitHub Issues（おすすめ度：★★★★★）

理由: 開発者が生のエラーログと解決策（Pull Requestやコメント）を議論している宝庫です。

方法: 既に GithubHandler や github_search.py があるようなので、GitHubのREST APIを使って is:issue is:closed label:bug などの条件で検索し、解決済みのIssueを収集するのがベストです。

② Qiita / Zenn（おすすめ度：★★★★☆）

理由: 日本語での具体的なエラー解決の知見が豊富です。

方法: どちらも公式APIを提供しています（Qiita API, Zenn API）。「エラー」「解決」などのタグやキーワードで定期的に記事を取得し、JSONにストックさせることができます。

③ Stack Overflow（おすすめ度：★★★★☆）

理由: 世界最大のエラー解決データベースです。

方法: Stack Exchange APIを利用します。スクレイピング（HTMLの解析）はBANされやすいサイトですが、APIなら合法かつ綺麗にデータ（質問とベストアンサー）が取れます。

④ 各種公式ドキュメント（おすすめ度：★★★☆☆）

理由: 根本的な仕様確認に必要です（例：React公式、FastAPI公式）。

方法: ここはスクレイピング（BeautifulSoup等）の出番です。ただし、構造がサイトごとに違うため、少し難易度が上がります。


Prompt Engineering Guide (プロンプトエンジニアリングガイド):

AIに対する効果的な指示の出し方が網羅されています。これをAI自身に記憶させ、「良いプロンプトの書き方を教えて」と質問できるようにすると、AIがAIの使い方をアドバイスしてくれるようになります。

LangChain / LlamaIndex の公式ドキュメント:

AIエージェントやRAGの設計パターンが豊富です。今後システムを拡張する際のアイデアの引き出しとして役立ちます。

Zenn や Qiita の「Ollama」「ローカルLLM」タグのついた記事:

「Ollamaのコンテキスト長を伸ばす方法」や「日本語に強いローカルモデルの比較」など、実践的な技術ブログはそのまま開発のナレッジベースになります。
